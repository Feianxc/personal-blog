大小母线调试问题平台

现场问题别丢，记下也找得到

现场调试一忙，问题很容易散在 Excel、照片和聊天记录里。等过几个月再遇到相似情况，记得当时处理过，却找不到完整过程。我做了这个平台，把项目、现象、照片、分析和解决方法放回同一条记录里。

现象 分析 处理 回看

我不想再靠翻聊天记录找答案

一次现场问题，往往有好几份材料：群里说了现象，手机里留了照片，Excel 里写了结论，真正的处理过程却在某个人的记忆里。材料都在，却很难拼成完整的一件事。这个平台先解决的就是这件小事：让一次问题从发生到解决都待在同一个地方。

一条问题会留下所属项目、现场现象、分析、解决方法、当前状态、分类、根因和照片。以后再查时，不只看到一句“已经解决”。

现场的一条问题，是这样留下来的

01 / 项目 先确认是哪个项目

问题跟着项目走，不会和别的现场记录混在一起。

02 / 现象 把当时看到的情况记下来

文字和现场照片放在一条记录里，少靠事后回忆。

03 / 处理 补上分析、根因和做法

处理过程中可以继续编辑，结论不必一次写死。

04 / 回看 更新状态，留给下次搜索

解决以后仍然能按项目、分类或关键词找回来。

我现在会在这里查什么、记什么

项目与问题

项目列表和问题台账放在一起

可以查看一个项目下有哪些问题，也可以从全部问题里回到对应项目。新增和编辑都走同一套记录方式。

现场记录

现象、照片和处理过程不会分家

问题描述、分析、解决方法、状态、分类、根因和现场照片都留在同一条问题里。

搜索

想得起一个词，就能先搜起来

项目和问题都支持搜索。遇到相似现象时，可以先看看以前有没有处理过，不必从文件夹一层层翻。

使用权限

能看、能改什么，不交给口头约定

平台有新增、编辑和权限管理。日常使用不会因为多人一起维护，就把记录改得没了边界。

查按项目和关键词找到旧问题
记把现象、照片、判断和处理留在一起
报按日期整理台账和汇报材料

到周报和阶段汇报时，不再临时拼材料

台账的价值不只是在现场查一次。平台可以按起止日期整理这段时间的问题，导出 Excel 台账，也能生成 PPT 汇报。项目、问题和处理结果本来就已经记好了，做汇报时只需要确定时间范围，再检查一次内容。

Excel 台账

适合继续筛选、统计和交接

按日期导出的表格保留问题明细，后续还可以继续整理，不需要再把网页内容手工抄一遍。

PPT 汇报

把这一阶段发生的事情直接排出来

汇报材料来自同一批问题记录，减少表格、照片和讲述之间互相对不上的情况。

电脑上先把记录理好，手机端还在接

平时我会在浏览器里整理项目、补问题、导出材料。小程序使用的 v2 接口已经部署，手机端还在联调，所以目前先以网页记录为准；等手机端接通以后，两边继续共用同一批项目和问题，不再单独维护一份台账。

页面使用 Next.js 16 和 React 19，数据部分由 Prisma 7 与 PostgreSQL 负责。技术只是把记录、搜索和导出稳稳接住，平时使用不需要关心这些名字。

材料可以收在一起，判断还得自己做

网页端已经上线并在持续维护。它能把材料放在一起，旧问题也更容易翻出来，但不会替我判断真正的根因。现场描述有没有写清楚，照片有没有拍到关键位置，处理结论能不能下次继续用，最后还是要由工程师确认。

现在的重点：继续把实际使用中遇到的分类、搜索和导出细节做好，让记录更容易补，也更容易在下一次调试时找到。
