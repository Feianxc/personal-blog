工作流札记 / workflow / 2026.04

一次个人站改版，怎样把想法留下以后还能查的轨道

一段对话会过去，文件、预览、日志和下一步如果留下来，任务才没有飘散。

这篇写的不是“AI 有多聪明”，而是一个任务如何落进现实：想法要变成文件，文件要跑出页面，页面要留下记录。下次回来时，不必从聊天记录的尘埃里重新寻找方向。

2026-04-20 个人工作流 Codex / Claude / 页面 / 预览记录

这轮工作流

目标 首页收口，内容页补材料，归档接住后续内容
改动范围 index / workflow / field / archive / css
执行方式 主控 + 内容修订 + 视觉检查
验证方式 preview / build / lint / screenshot

这里不聊榜单排名，只记一件事：下次回来能不能接着做。

这轮实际留下了什么

以前很多想法都散在对话里：当时能推进，过两天再回来就要重新解释一遍。现在更需要一套能续上的记录——不只保留结论，也把任务、页面、日志和判断一起留下来。

以前会卡住 想法很多，但过程散在对话和脑子里

当时能推进，隔几天再回来就容易断线，还得重新找上下文。

这轮补上的缺口 页面、记录、进度和判断都能落到文件上

这样下一轮回来，不用再靠记忆接手，而是能顺着材料接着做。

对我最有用的变化 更大的任务也能慢慢接上，而不是只停在试试

从个人站到现场记录，这套记录方式开始能接住更长一点的任务。

三条原始记录

决定下一轮往哪改的不是“感觉差不多了”，而是这几篇记录：预览是否在线、质量是否暴露问题、优先级是否锁死。

preview.log

Port 4173 is in use, trying another one...
Port 4174 is in use, trying another one...
Port 4175 is in use, trying another one...
Local: http://127.0.0.1:4176/

这条记录直接推翻了“预览地址会固定不变”的想当然。

lighthouse_clean.json

"finalUrl": "http://127.0.0.1:4176/"
"performance": 0.55
"accessibility": 1
"displayValue(FCP)": "11.2 s"
"displayValue(LCP)": "11.3 s"

页面能打开不代表结束，指标会把问题摊出来。

progress.md

下一轮执行优先级正式锁定为：
1. 正文页硬材料
2. 字体人格
3. 首页真实前景模块

这条记录比“我记得我想改什么”更可靠，因为下一轮能直接顺着它接下去。

这轮我改了哪些判断

现在会少写“做了很多”这种模糊表达，更愿意把判断写清楚：保留了什么、推翻了什么、最后落到哪里。

判断 保留 / 推翻依据 落点
固定端口预览 推翻。真实预览日志已经显示 4173 / 4174 / 4175 全被占用，最后才落到 4176。 site/logs/preview.log
页面能打开就算完成 推翻。Lighthouse 直接把 0.55、11.2 s、11.3 s 摆出来。 site/reports/lighthouse_clean.json
正文页先讲态度 推翻。长期记录已经把优先级锁成“先补正文页硬材料，再改归档结构”。 progress.md
继续补真实入口和材料 保留。增益不在多会说，而在页面更像真站。 index.html / workflow.html / field.html

后续接手的位置

这套记录有用的地方不是把事情说圆，而是把没做完的地方留下来。

这轮还没做完

  • 首页的人物主语还要继续收，系统标签仍然偏多。
  • field.html 还缺更强的 incident header、排除树和交接项。
  • 动效现在主要集中在首页，内容页的反馈还不够强。

后续对象

  • site/field.html：补现场物证带和假设排除树。
  • site/src/entry.css：拉开 workflow / field 的行为差异。
  • site/index.html：继续减少概念包装，把主页语气收得更自然。

后面更在意的是：想法能不能真的做出来，下次能不能接得上。
