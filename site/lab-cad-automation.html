先把 CAD 研究目录从业务仓库里拆出来

如果 CAD 研究、调试和运行产物继续堆在业务仓库里，后面无论成功多少次，都会越来越难接手。所以这轮先把 CAD 自动化工作台从业务仓库里拆出来，让研究资产、配置、样本和 runs 各归各位。

run root 里现在要看哪些东西

对象 现在放在哪 放置理由
研究与归档 archive/ / docs/ 不再让调试残骸和业务正式输出混在一起。
配置与样本 configs/ / samples/ 每次运行都能对上样本批次和配置来源。
执行入口 tools/bmc10_fullsheet_publish.py 把全量发布流程固定成一个能重跑的 CLI。
运行清单 runs/fullsheet_publish_*/manifest.json 这让“上次到底发布了什么”不再只能靠回忆。
业务侧素材输出 artifacts/material_library/pending 工作台负责调试和产出，业务仓库只接最终需要的素材。

不再靠手拖窗口

full_extents.png full_extents.json all_sdlx_texts_raw.txt modelspace_bmc_texts_raw.txt manifest.json 
当前可复用 CLI：
bmc10_fullsheet_publish.py

使用：
1. 已验证成功的 full_extents.png / full_extents.json
2. 两份文本 raw
3. 投影定位 + 局部裁切 + caption 发布

输出：
- artifacts/material_library/pending/start
- artifacts/material_library/pending/busbar
- runs/fullsheet_publish_/manifest.json

这条流程最有用的地方，是它不再强依赖“实时拖 CAD 窗口把缩放调对”。一旦全图导出和文本锚点已经成立，后面更多是坐标和发布问题，而不是手工操作技巧。
