工具清单 / 使用建议 / 本次任务

Context Router V1：能力只在需要时进场

我先把可用工具列成清单。需要某项能力时，它只给建议，由我确认；任务结束后就收回。

工具一多，很容易在不知不觉中全部打开。久了以后，连自己都说不清某个工具为什么进来、什么时候该退出。我做这个小路由器，是想让每次启用都有理由，也能随时关掉。第一版很克制，只提醒，不替我做决定。

2026-04-23 整理router / bundle / governancesuggest + attach + route-log

第一版只管四件事

清单把工具的用途、位置和风险记下来
建议根据当前任务给出少量候选
读取平时只记名字，需要时再打开说明
收录新工具先检查，再决定要不要加入

我不想让所有工具自动进场。看得见原因，才知道什么时候该收回。

先说规矩：它只给建议，不会自己切换

最开始我也想过让它更主动，听到一句话就自动换工具。很快就发现不对：这样虽然省了一次点击，却把使用原因藏了起来。第一版只显示建议和理由，由我决定是否启用。

启用以后也只对当前任务生效。换了项目或结束这次工作，它不会把旧状态悄悄带过去。

它需要记住哪些能力，又要忘掉什么

内容放在哪里解决什么问题
工具清单.codex/router/catalog.json记住名称、用途、位置和风险，避免临时猜。
常用组合bundles.toml常一起使用的工具由人整理，不让程序随便凑。
本次状态.workspace/skillos/state.json只记录这一次启用了什么，任务结束后就清掉。
建议记录route-log.jsonl以后能回看当时为什么推荐它。
待审区inbox/新工具先放这里检查，不直接写进正式清单。

临时启用的能力，只留在这一次任务里

普通任务直接做只给建议本次有效由人确认
普通工具够用时，不额外推荐
确实需要专用能力时，说明原因
由我确认以后，才在当前任务中启用
任务结束、切换组合或手动关闭时收回
新工具先检查，再进入正式清单

这套做法看起来慢半步，却能避免工具越开越多。对长期项目来说，知道为什么用，比自动打开更省事。

现在有目录和数据草图，还没有成熟运行版

目录已经分清

正式清单、待审区和本次任务状态各有位置，后面实现时不用再讨论文件应该放哪。

几个配置文件先定了职责

catalog.json 记工具，bundles.toml 记组合，state.json 只记本次状态。

建议必须说明理由

路由记录会留下触发原因和候选项，不能只给一句“系统认为合适”。

故意不做的事也写清楚

不跨项目继承，不静默改全局配置，也不按一句话自动开关插件。

这几件事，我暂时不会让它自动做

现在还只是蓝图

  • 工具清单还需要从真实环境里挑一小批初始化。
  • 启用和收回的交互还要在实际任务里试。
  • 第一版不会追求自动识别所有意图。

下一步只做小样

  • 先放十几个最常用的工具。
  • 只写少量把握很高的推荐规则。
  • 跑几次真实任务，再决定要不要扩展。

我希望它像一个会提醒我的工具箱，不像一个会自己抢方向盘的司机。
