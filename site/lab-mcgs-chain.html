我不想每个项目都靠记忆重新拼一遍

一个 MCGS 项目真正动起来，牵涉的不只是几个画面。配方字段变了，数据库、设备、策略、报警和窗口里的对应内容也可能要跟着变。以前这些关系散在不同文件和操作里，少改一处，往往要到后面才发现。

我现在保留一份固定模板，把每个项目会变化的内容单独拿出来。装配台只问这一次项目需要什么，其余内容从模板里接上。

从模板到当前项目，我会走四步

01 / 模板 先选固定模板

公共结构留在模板里，不再为每个新项目从头搭一次。

02 / 参数 只填这次真正会变的内容

屏数、列数、箱型和现场差异放在同一个入口里确认。

03 / 装配 让六块清单一起更新

配方、数据库、设备、策略、报警和窗口计划同步刷新。

04 / 确认 再回到 MCGS 完成验证

另存、回读、编译和仿真仍在正式软件里完成。

六块容易漏的内容，放进一张清单

配方 + 数据库

先把对象和字段排清楚

需要新增、沿用或调整的内容会落在清单里，避免在不同窗口之间来回找名字。

设备 + 策略

设备结构一变，相关代码跟着换

哪些策略沿用，哪些脚本要生成，都会按当前项目重新列出来。

报警 + 窗口

报警和画面不再留到最后补

对应的报警内容、窗口安排和需要检查的位置，会和前面的参数放在一起看。

动环三件套

协议、设备导入表和状态代码一起接进来

动环协议 Excel、MCGS 设备导入 CSV 和报警状态字代码可以继续沿用同一份项目数据。

改一个参数，马上知道后面会动哪里

装配台最实用的地方，是我能立刻看见一个改动会影响什么。参数变化以后，相关清单、代码和窗口计划会马上刷新，而不是等我打开几个文件以后才想起还有一处没改。

一个具体例子

单屏单列，不再带出第二物理列

当项目选成单屏单列时，第二条物理列会从清单、代码和窗口安排里一起排除，不需要我再到各处手动删除。

我真正想省下的时间

不是少点几下鼠标，而是少做几轮重复核对

参数和结果放在同一个视图里，我可以先把变化看明白，再进入 MCGS 做正式操作。这样更快，也更容易发现不合理的组合。

装配台把准备工作做齐，最后还得回 MCGS 确认

装配台不会直接改写原始 MCP 工程。每次都从固定模板、副本和输出清单开始，原版始终保留。它能整理该改什么、生成需要的代码和安排，但正式工程仍要在 MCGS 里一步一步确认。

仍要完成

另存为、回读、重新提取、编译和仿真

生成内容进入工程后，我还会在 MCGS 里另存为（Save As）、通过软件界面回读，再做重新提取、编译和仿真。

最终边界

现场确认不能被一张清单代替

画面、通讯和实际设备能不能按预期工作，最后仍要通过现场确认。新的箱型也还在继续接入模板。

当前状态：装配台已经能把项目参数和主要改造内容连起来；更多箱型正在陆续接入，MCGS 内的正式验证流程不会省略。
