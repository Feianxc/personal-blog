OHBP / harnessbench：先把测试材料留全，再看排名

一次测试至少要留下协议版本、运行清单、最终材料包和复核记录。

排行榜很直观，也最容易把过程藏掉。只看一个分数，我不知道它在哪台机器上跑、有没有挑最好的一次，也不知道中间是否手工改过。这个项目先把原始材料留全，再让复核程序给出结果，网页只负责展示。

2026-04-23 整理TypeScript 单体仓协议 / 打包 / 复核 / 页面

先把四样东西分开

协议规定任务、文件和允许的做法
运行记录环境、参数和原始输出
打包统一命令把文件收成材料包
复核verification_record 只由复核程序生成

网页可以显示成绩，但不能自己给成绩盖章。

分数出来以前，先把原始材料留全

一次评测如果只剩最后的分数，过几天就很难回答：谁跑的、怎么跑的、有没有重试很多次、环境有没有影响。我把一个成绩拆成协议版本、运行记录、材料包和复核结果。少了其中一项，就先不急着上榜。

协议、运行记录、材料包和复核结果，不能混在一起

内容位置负责什么
协议docs/ohbp-v0.1/ohbp-v0.1.md规定任务、文件格式和允许的操作。
实现说明docs/implementation/build-blueprint.md说明各个程序先做什么、后做什么。
公共规则packages/schema / validator-core命令行、复核程序和网页读取同一套定义。
应用入口apps/hb-cli / verifier-worker / web运行、复核和展示各管一段，谁也不能既当选手又当裁判。
结果文件manifest.json / verification_record前者记录这次运行，后者记录复核程序的判断。

一份结果上榜前，要先过几道关

运行打包检查模拟上传复核展示
hb run       保存原始输出
hb pack      收成最终材料包
hb validate  检查文件和字段
hb upload    先走模拟接收
复核程序      生成 verification_record
web          读取结果并展示排名

每个入口只做自己的事。运行命令不宣布胜负，网页也不能绕过复核程序直接写结果。

每个分数都要能回到那次运行

协议版本先固定

OHBP v0.1 先写清任务和文件约定。规则变化时，成绩也能知道自己属于哪个版本。

运行清单把文件串起来

manifest.json 记录环境、参数、原始输出和摘要，材料不会只剩一个散落的压缩包。

网页只读取复核结果

页面可以做官方榜、实验榜或单条详情，但不能自己改复核结论。

原始输出始终保留

分数异常时可以回到那次运行，而不是围着排行榜猜原因。

榜单可以晚一点，规则和材料不能省

这次先不做

  • 不定义一个包打天下的全球总榜。
  • 不把运营积分塞进评测协议。
  • 不让某个页面单独拥有全部规则。

接下来

  • 补一组正常样本和故意破坏的样本。
  • 把 hb pack 的打包结果跑稳。
  • 材料和复核稳定以后，再继续做榜单视觉。

我先问“这份成绩能不能被重新检查”，再问“它排第几”。
