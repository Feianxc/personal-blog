动环协议工作台：把四种出表场景放进同一个入口

客户填完参数后，Excel、校验结果、源模板对比 和 交付状态 要从同一个入口返回。

这种事情最容易停在半手工：模板很多、规则很多、场景很多，最后每次都像重新翻一次历史项目。现在这套仓库至少把四个一线出表场景、单页客户工作台、smoke test 和交付包一起收住了。

旧模板不再靠人工翻找

过去每来一个新项目，都要重新猜模板、表头和 A/B 路默认值。现在四个主场景、关键默认值和交付判断被放到同一张台面上。

四个出表场景先摆到同一页

场景 family / topology 作用
标准单列 classic_combined / single_screen_one_column 这是最常规的一线说法，先把它钉住，后面的比较才有基准。
单屏双列 classic_combined / single_screen_two_columns 它直接接入浙江农商行双列源模板，是这次“不是玩具”的关键材料之一。
扩展版 extended_split / single_screen_half_channel 说明系统不是只会出一种最简表，而是已经开始覆盖复杂工作表结构。
A / B 分屏版 ab_screen_split / dual_screens_ab_separated A/B 路别和地址摘要能按真实场景输出，不再靠人手后处理。

客户打开的是这个工作台

单工作台，而不是 basic / advanced 分裂

README 里直接写明：当前前端已经调整成单工作台 + 结果后置的客户填写页。这说明这轮开始处理“给客户怎么填、怎么看结果”，而不是继续加后台选项。

B 路默认值被写成了可复核的事实

S2、201、单屏双列下的默认始端箱序列，都被明确写进了 README 和 smoke test。 它把“按记忆处理”改成了“仓库承认当前说法”。

分享包已经能让别人解压就跑

share bundle 的说明很清楚：先解压、双击 start_studio.bat、首次会自动建 .venv 并安装依赖、浏览器自动打开 127.0.0.1:8123。 它不再只依赖开发机里的研究脚本。

前端价值不在更花，而在按“客户会怎么填、怎么判、怎么拿走 Excel”组织界面。

加模板前的核查对象

还没做完

  • 当 A / B 路设备很多时，单页仍会变长，信息密度还得继续压。
  • source_compare 已足够做工程回归，但 README 也明确承认它不是司法鉴定式逐格证明。
  • 核心资产目前还压在 .workspace/codex-swarm/... 里，后续最好迁进正式 assets/ 目录。

后续对象

  • 核查四个场景的说法是否被新需求冲乱。
  • 核查 smoke test 是否仍覆盖关键默认值和双列场景。
  • 新增模板族放在后面；没有新材料前，不把工作台拆回多模式。

这件事能成立，不靠“它能生成 Excel”这句话，而靠填参、校验、交付状态和启动方式一起说清楚。
